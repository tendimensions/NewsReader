# Skill: Hive Storage

Reference for working with Hive models and repositories in this project.

## Overview

All local persistence uses **Hive** (NoSQL box storage). Models are annotated with `@HiveType` / `@HiveField`, and type adapters are generated by `build_runner`.

## Registered Type IDs

| typeId | Class | File |
|--------|-------|------|
| 0 | `Article` | `lib/models/article.dart` |
| 1 | `FeedConfig` | `lib/models/feed_config.dart` |
| 2 | `ThemePreference` *(enum)* | `lib/models/app_settings.dart` |
| 3 | `AppSettings` | `lib/models/app_settings.dart` |

**Always pick the next available typeId** when adding a new model. Never reuse a typeId even if the old model is deleted — doing so causes runtime crashes on devices that have the old data stored.

## Modifying a Model

1. Edit the model file (`lib/models/<model>.dart`)
2. Regenerate the adapter:
   ```bash
   dart run build_runner build --delete-conflicting-outputs
   ```
3. Commit **both** the model file and its generated `*.g.dart` file
4. If you added fields, consider migration (see below)

## Adding a New Model

```dart
import 'package:hive/hive.dart';

part 'my_model.g.dart';

@HiveType(typeId: <next_available_id>)
class MyModel extends HiveObject {
  @HiveField(0)
  final String id;

  @HiveField(1)
  final String value;

  MyModel({required this.id, required this.value});
}
```

Then run code generation and register the adapter in `main.dart`:

```dart
Hive.registerAdapter(MyModelAdapter());
```

## Repositories

Each Hive box has a dedicated repository in `lib/repositories/`:

| Repository | Box name | Stores |
|------------|----------|--------|
| `BookmarksRepository` | `bookmarks` | Bookmarked `Article` objects |
| `ArticleCacheRepository` | `article_cache` | Cached articles (max 200) |
| `FeedConfigRepository` | `feed_configs` | `FeedConfig` objects + defaults |
| `SettingsRepository` | `settings` | `AppSettings` singleton |
| `ArticleStateRepository` | `article_state` | Read/deleted article ID sets |

Repositories are provided as singletons via Riverpod in `lib/providers/repositories_provider.dart` (overridden in `main.dart` after Hive initialises).

## Data Migration

Hive does not have built-in migrations. To handle schema changes:

- **Adding nullable fields**: safe — old objects will have `null` for new fields
- **Adding non-nullable fields**: requires a default value or a migration step in the repository constructor
- **Removing fields**: safe — old data for removed fields is ignored on read
- **Renaming fields**: not possible by name; use `@HiveField` index to preserve binary compatibility
- **Breaking changes**: increment the typeId, write a one-time migration on first open, then delete the old box

## Generated Files

Never edit `*.g.dart` files manually. They are regenerated by:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Commit generated files alongside the model source — CI depends on them being present.
